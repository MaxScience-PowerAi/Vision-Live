## Les problèmes qu'on a rencontrés et comment on les a résolus

Cette partie est précieuse à l'oral : elle montre que tu as **vraiment** construit et débogué le système.

%cols 26,37,37
| Problème | Cause | Solution |
|---|---|---|
| Le micro donnait n'importe quoi | Gain du micro trop fort : son écrêté (saturé) | « Internal Mic Boost » à 0, entrée à 35 % (`wpctl set-volume @DEFAULT_AUDIO_SOURCE@ 0.35`) ; le code détecte aussi un micro saturé |
| Whisper répétait une phrase en boucle | « Hallucination » sur du bruit | Filtre passe-haut, détection du silence, `no_repeat_ngram_size`, rejet des phrases trop répétitives |
| Le vérificateur ne servait à rien | Le tokenizer du dépôt remplissait les phrases avec le n° 49407 : toutes les phrases semblaient identiques | Tokenizer CLIP standard `ViT-B-32` |
| Grandes lignes parasites sur les contours | `masks.xy` reliait les morceaux d'un objet | Contours recalculés avec `cv2.findContours` |
| Plantage du suivi | Le mode ReID « auto » n'est pas compatible avec YOLOE | `with_reid: False` |
| Téléchargement de Qwen bloqué à 0 octet | Le système de téléchargement « xet » de Hugging Face | `HF_HUB_DISABLE_XET=1`, reprise avec `curl -C -`, vérification SHA256 |
| Qwen refusait de se charger | Fichier unsloth : 6 couches non compressées non déclarées ; couches BF16 | Les deux réparations de `charger_qwen.py` |
| Qwen cassé 2 fois sur 3 | Deux modèles chargés en même temps | Verrou `CHARGEMENT` |
| La fenêtre se fermait (I puis V, 2 caméras) | Mémoire graphique pleine dans YOLOE | Whisper sur CPU quand Qwen est réveillé, mise en veille de Qwen, image sautée au lieu de planter |
| « Personne » mal vue sur l'iPhone | Analyse de l'image réduite avec bandes noires (0,35 au lieu de 0,92) | Analyser l'original puis `recadrer()` |
| Icônes blanches en haut de la fenêtre | Barre d'outils Qt sans polices | `cv2.WINDOW_GUI_NORMAL` (pas de barre) |
| Fermer avec la croix plantait | Erreur OpenCV « NULL guiReceiver » | `getWindowProperty` dans un `try/except` |
| Voix robotique au démarrage | espeak parlait pendant que Kokoro chargeait | Piper parle d'abord ; on attend jusqu'à 15 s plutôt qu'espeak |
| Vidéos illisibles sur téléphone | cv2 ne sait pas écrire le H.264 | PyAV `libx264` |
| Vidéo accélérée | Rythme de la fenêtre variable | Répéter ou sauter des images pour rester à l'heure |

## Les limites honnêtes

- **Réglé pour une pièce** : les seuils et les 77 exemples viennent de ta chambre et de ta webcam.
- **Faux « chat »** vu à 0,41 sur l'iPhone face au clavier : risque de fausse alerte animal.
- **Le code est dans un notebook** avec une fenêtre OpenCV : très bien pour un prototype, pas pour un produit (il faudrait un service qui tourne en fond et une interface web).
- **Pas de caméras IP (RTSP)** : celles qu'utilisent les entreprises. Techniquement proche (une adresse `rtsp://...` dans `CONFIG["cameras"]`), mais pas testé.
- **Aucun test automatique** complet ; `lancer()` fait environ 550 lignes.
- **Qwen ralentit** la fenêtre pendant qu'il réfléchit (≈ 21 → 11 images/s) et la fige ≈ 1 s quand il se réveille.

# Questions qu'on pourrait te poser

### « Tu as entraîné ton propre modèle ? »
Non, pas depuis zéro : ça demanderait des millions d'images et des semaines de calcul. J'utilise des modèles pré-entraînés (YOLOE, MobileCLIP2, Whisper, Qwen) et je les **adapte** : un adaptateur que j'entraîne sur mes corrections en 0,2 s, une mémoire kNN, et des prototypes qui modifient les signatures du détecteur. Ça fait passer la précision de 59 à 80 % sur mes vraies images.

### « Pourquoi pas juste YOLO classique ? »
YOLO classique ne connaît que 80 classes fixes (celles du jeu de données COCO). YOLOE accepte n'importe quelle liste d'objets en texte, et même un objet montré à la souris. J'en ai mis 230, dont des objets locaux (manioc, plantain, chaise en plastique).

### « Pourquoi un deuxième modèle pour vérifier ? »
Parce que YOLOE seul n'avait que 19 % de noms justes sur mes vraies images : il voit toute l'image réduite, l'objet n'y fait que quelques pixels. MobileCLIP2 regarde chaque objet de près, sans le fond, et rejette les mains, le flou, les murs.

### « Comment les objets gardent-ils leur nom ? »
Un suivi BoT-SORT donne un numéro à chaque objet d'une image à l'autre. Le nom est voté sur les 15 dernières images, le score est lissé, et il faut 3 images pour apparaître. Le seuil pour rester est plus bas que pour apparaître (hystérésis), donc ça ne clignote pas.

### « Comment ça tient sur 6 Go de mémoire graphique ? »
YOLOE et MobileCLIP2 en FP16 prennent 0,54 Go. Qwen est compressé en 4 bits (4,3 Go) et ne se charge qu'à la demande ; quand il est là, Whisper passe sur le processeur. Il se rendort après 2 minutes. J'ai mesuré le pic : 5,17 Go sur 5,6 utilisables.

### « Pourquoi tout en local ? »
Confidentialité (les images ne quittent pas le PC), pas d'abonnement, et ça marche sans internet (ma connexion est lente et souvent coupée). Seules les alertes Telegram ont besoin d'internet, et elles attendent sur le disque sinon.

### « Comment tu as su que tes réglages étaient bons ? »
J'ai annoté à la main 74 vraies détections et j'ai écrit un banc de test qui rejoue le vrai code du notebook. Chaque seuil a été choisi en mesurant. Pour l'apprentissage, j'ai utilisé une validation croisée pour ne pas tricher.

### « Comment le clip peut-il commencer avant l'alerte ? »
L'enregistreur garde en permanence les 10 dernières secondes dans un tampon circulaire de 100 images JPEG. Quand une alerte part, il copie ce tampon et continue 10 secondes.

### « Qu'est-ce qui manque pour le vendre ? »
Régler les licences (YOLOE en AGPL, MobileCLIP2 en recherche seulement), supporter les caméras IP, transformer le notebook en service avec une interface web, mesurer les fausses alertes, et respecter le RGPD.

# Glossaire

%cols 22,78
| Mot | Explication |
|---|---|
| Adaptateur | Petite matrice W (512 × 512) entraînée sur tes corrections, ajoutée aux signatures du vérificateur |
| API | Une façon pour deux programmes de se parler (ici : Telegram par des requêtes web) |
| BoT-SORT | Algorithme de suivi d'objets d'une image à l'autre |
| Boîte (xyxy) | Rectangle autour d'un objet : coin haut gauche (x1, y1), coin bas droit (x2, y2) |
| CLIP | Modèle qui met images et textes dans le même espace de signatures |
| CUDA | La technologie de NVIDIA pour calculer sur la carte graphique |
| Dataset | Jeu de données d'exemples (images + bonnes réponses) |
| EMA | Moyenne mobile exponentielle : `ema = 0,7 × ema + 0,3 × nouveau` |
| Embedding / signature | Liste de nombres (ici 512) qui résume une image ou un texte |
| Époque | Un passage complet sur tous les exemples pendant l'entraînement |
| FP16 / BF16 / 4 bits | Façons de stocker les nombres avec moins de place |
| H.264 | Format de compression vidéo lisible partout |
| Hystérésis | Seuil d'apparition plus haut que le seuil de disparition, pour éviter le clignotement |
| Inférence | Utiliser un modèle déjà entraîné |
| IoU | Recouvrement de deux boîtes : surface commune / surface totale |
| kNN | « k plus proches voisins » : on décide d'après les exemples les plus ressemblants |
| Long polling | Requête que le serveur garde ouverte jusqu'à ce qu'il ait une réponse |
| Masque | Les pixels exacts d'un objet (segmentation) |
| Prompt visuel | Montrer un objet en image au lieu de le décrire en texte |
| Prototype | Signature moyenne de tes images d'un objet, mélangée au texte dans YOLOE |
| Régularisation | Pénalité qui empêche un modèle de trop s'éloigner de son point de départ |
| Softmax | Fonction qui transforme des scores en probabilités |
| Tampon circulaire | File de taille fixe : quand elle est pleine, le plus ancien élément sort |
| Thread | Fil d'exécution qui avance en parallèle dans le programme |
| Tokenizer | Découpe un texte en numéros de mots pour le modèle |
| Validation croisée | Tester sur des exemples jamais vus à l'entraînement, en tournant les paquets |
| VLM | Modèle de langage qui comprend aussi les images (Qwen3-VL) |
| Vocabulaire ouvert | Détecteur à qui on donne la liste des objets à chercher, au lieu d'une liste fixe |
| VRAM | Mémoire de la carte graphique |
